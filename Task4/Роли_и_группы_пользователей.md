# Задание 4. Роли и группы пользователей Kubernetes (PropDevelopment)

Разграничение доступа построено по организационной структуре компании. Продуктовые команды работают в
неймспейсах своих доменов (`sales`, `zhku`, `finance`, `data`), а cross-доменные группы получают доступ
через ClusterRole. Доступ выдаётся по принципу минимальных привилегий: роли, которым не нужны секреты,
не имеют на них прав.

## Таблица ролей

| Роль | Права роли | Группы пользователей |
| --- | --- | --- |
| `cluster-viewer` (ClusterRole) | Только просмотр ресурсов кластера: `get`/`list`/`watch` на pods, pods/log, services, configmaps, namespaces, nodes, endpoints, deployments, replicasets, statefulsets, daemonsets, jobs, cronjobs, ingresses. Доступ к secrets не выдаётся. | Операционные менеджеры (группа `managers`), бизнес-аналитики (группа `business-analysts`) |
| `cluster-privileged` (ClusterRole) | Всё, что у `cluster-viewer`, плюс просмотр привилегированных данных: `secrets`, `events` во всех неймспейсах, просмотр RBAC-объектов (`roles`, `rolebindings`, `clusterroles`, `clusterrolebindings`) — для аудита доступа. | Специалист по информационной безопасности (группа `security`), BI-аналитики (группа `data-analysts`) |
| `cluster-operator` (ClusterRole) | Настройка кластера во всех неймспейсах: создание/изменение/удаление pods, configmaps, secrets, services, serviceaccounts, deployments, statefulsets, jobs, cronjobs, ingresses, storageclasses; `get`/`list`/`watch`/`patch` на nodes (пометки, тэинты). Управлять самим кластером (`create`/`delete` namespaces и т. п.) не позволяет. | DevOps-инженеры (группа `devops`) |
| `domain-developer` (Role, создаётся в каждом доменном неймспейсе) | Развитие приложений **в своём домене**: управление pods (включая логи), configmaps, services, deployments, replicasets, statefulsets, jobs, cronjobs, ingresses внутри своего неймспейса. Доступ к secrets и к ресурсам других неймспейсов не выдаётся. | Разработчики доменов: `sales-dev` (sales), `zhku-dev` (zhku), `finance-dev` (finance), `data-dev` (data) |

## Сопоставление пользователей и ролей

Пользователи создаются как сертификаты, подписанные CA кластера: `CN` = имя пользователя, `O` = группа
(см. `create_users.sh`). Привязка пользователей к ролям выполняется через `RoleBinding`/`ClusterRoleBinding`
с субъектом `kind: User` (см. `create_bindings.sh`).

| Пользователь (CN) | Группа (O) | Роль | Область действия |
| --- | --- | --- | --- |
| `devops-pavel` | `devops` | `cluster-operator` | весь кластер |
| `security-ivan` | `security` | `cluster-privileged` | весь кластер |
| `bi-anna` | `data-analysts` | `cluster-privileged` | весь кластер |
| `manager-marina` | `managers` | `cluster-viewer` | весь кластер |
| `ba-dmitry` | `business-analysts` | `cluster-viewer` | весь кластер |
| `sales-oleg` | `sales-dev` | `domain-developer` | неймспейс `sales` |
| `zhku-nikolay` | `zhku-dev` | `domain-developer` | неймспейс `zhku` |
| `finance-ekaterina` | `finance-dev` | `domain-developer` | неймспейс `finance` |
| `data-pavel` | `data-dev` | `domain-developer` | неймспейс `data` |

## Состав файлов

| Файл | Назначение |
| --- | --- |
| `create_users.sh` | Создание пользователей: сертификаты, подписанные CA кластера (CN/O), и готовый kubeconfig на каждого. `--delete` — удалить сгенерированные сертификаты. |
| `create_roles.sh` | Создание неймспейсов доменов, ClusterRole (`cluster-viewer`, `cluster-privileged`, `cluster-operator`) и Role `domain-developer` в каждом доменном неймспейсе. `--delete` — удалить. |
| `create_bindings.sh` | Привязка пользователей к ролям: `ClusterRoleBinding` для cross-доменных групп и `RoleBinding` в неймспейсах доменов. `--delete` — удалить. |
| `test_rbac.sh` | Тестирование: проверка разрешённых и запрещённых действий для каждого пользователя (через `auth can-i` и через реальные сертификаты). |

## Порядок применения

```bash
./create_users.sh       # 1. создать пользователей
./create_roles.sh       # 2. создать неймспейсы и роли
./create_bindings.sh    # 3. связать пользователей с ролями
./test_rbac.sh          # 4. проверить разграничение доступа
```
